# 智能排版运行时改造计划

## 背景

当前 Word 智能排版已经具备语义映射、AI 标注、渲染、撤销和前端确认卡片，但主链路仍然存在几个结构性问题：

- 预览方案与最终执行不是同一个任务对象。预览阶段保存 `ReformatPreviewPlan`，点击应用后又从当前 Word 选区重新收集段落并重新发起语义标注。
- 用户在预览后移动光标或改变选区，最终执行范围可能偏离用户确认的范围。
- 意图识别仍以规则为主，LLM 微调能力存在但 Word 主链路没有稳定使用。
- 内置标准、用户模板、样式指南、docx 映射和格式克隆结果没有统一成一个标准注册中心。
- “换一种”只完成了重新分析，指定模板/标准分支仍是占位逻辑。
- 表格、图片、公式、页眉页脚、页码等结构被检测到，但大多只跳过，不能满足真实文档排版需求。

## 目标

建立一条稳定的排版运行时链路：

1. 捕获固定范围，生成 `ReformatJob`。
2. 识别用户意图，产出结构化 `ReformatIntent`。
3. 从统一标准注册中心选择候选标准。
4. 生成可执行 `ReformatPlan`，预览和执行使用同一个计划。
5. 执行后校验结果，提供可靠撤销。
6. 支持候选标准切换、用户模板、RAG/知识库、Skills/MCP 扩展。

## 分阶段计划

### P0 固定排版任务范围

状态：已完成

交付：

- 已新增 `ReformatJob` 作为一次排版任务的上下文容器。
- 已在生成预览方案时记录文档名、范围起止、段落对象、段落文本、样式、类型、字号、加粗信息。
- `应用排版`、`微调`、`换一种` 已优先使用当前 `ReformatJob`，不再依赖当前 Word 选区。
- 已保留旧入口兼容性：直接从模板/规范入口排版时，仍从当前选区创建临时 job。

验收：

- 生成预览后移动光标，再点击应用，仍作用于原始范围。
- 微调方案不因当前选区变化而丢失段落上下文。
- 构建通过。

### P1 LLM 意图识别

状态：已完成

交付：

- 已新增 `ReformatIntentRecognizer`。
- 已输出结构化 JSON：意图类型、范围、文档类型、标准偏好、具体格式要求、置信度。
- 已接入 Word 聊天排版主链路：先识别意图，再把 `FormatIntent` 传给编排器生成方案。
- 已修正 `ReformatService` 的 AI 委托注入，并让 Word 侧复用带 LLM 能力的 `ChatFormatterAgent`。
- 规则识别作为 fallback，LLM 不可用、返回空或解析失败时不阻塞。

验收：

- “按公文格式排版”“标题再醒目一点”“表格统一三线表”“页码放右下角”等需求能区分意图和对象。

### P2 统一标准注册中心

状态：进行中（第一批已完成）

交付：

- 已新增 `FormattingStandardRegistry`。
- 已统一加载内置标准、用户模板、已转换样式指南、docx 映射。
- 标准候选已带来源、适用类型、置信度、可解释原因。
- 已让 `SmartFormattingOrchestrator` 通过 registry 选择标准。
- 已让 `ReformatIntentRecognizer` 的可用标准列表读取 registry，因此用户模板/docx 映射能参与 LLM 意图识别。
- 待补：格式克隆结果进入 registry；前端候选选择与 `switchFormattingTemplate(templateName)` 的完整闭环。

验收：

- “换一种”可以列出真实候选并按候选重建方案。
- 用户上传的模板和样式指南能自动参与推荐。

### P3 可执行 ReformatPlan

状态：待做

交付：

- 将 `ReformatPreviewPlan` 拆分/升级为 `ReformatPlan`。
- 明确每个段落的目标语义标签、目标格式、页面设置和跳过原因。
- 预览卡片、对比、执行、撤销都读取同一个计划。

验收：

- 预览中展示的目标标签和最终执行标签一致。
- AI 标注只用于生成计划，不在确认后再次改变意图。

### P4 候选切换与对比

状态：待做

- 完成 `switchFormattingTemplate(templateName)` 后端实现。
- 支持候选标准 A/B 对比。
- 对比不只展示文本摘要，还能展示真实格式差异。

验收：

- 前端点击“换一种”或选择候选标准后，卡片更新为对应方案。

### P5 复杂文档结构支持

状态：待做

验收：
