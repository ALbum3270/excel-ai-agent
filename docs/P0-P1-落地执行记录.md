# P0/P1 优化落地执行记录

更新时间：2026-06-08

## 采纳结论

`深度分析报告.md` 和 `P0-P1-实施方案.md` 的方向可以采纳。当前代码扫描结果证明其中几个问题真实存在：安装包引用 Debug 输出、版本号脱节、短生命周期 HttpClient 分散创建、WebView2 只预热 loader 未缓存 environment、正式签名缺少工程入口。

## 本次已落地

### P0-2 安装包 Release 配置

- `OfficeAgent/OfficeAgent.vdproj` 的 `bin\Debug` 输出引用已切换为 `bin\Release`。
- `.NET Framework LaunchCondition` 的 `AllowLaterVersions` 已改为 `TRUE`。
- 已删除安装包中的 `.pdb/.xml` 文件块。
- 新增 `build/AuditInstallerRelease.ps1`，用于检查 Debug 输出、较高 .NET 版本限制和 PDB/XML 安装项。
- 新增 `build/CleanInstallerDebugSymbols.ps1`，用于按 vdproj 文件块清理 PDB/XML 安装项。

验证：`powershell -ExecutionPolicy Bypass -File .\build\AuditInstallerRelease.ps1` 通过。

### P0-3 统一版本策略

- 新增 `Version.txt`，当前版本为 `2.8.0`。
- 新增 `build/UpdateVersion.ps1`。
- 新增 `build/AuditVersion.ps1`，用于只读校验 `Version.txt`、AssemblyInfo、VSTO `ApplicationVersion` 和 MSI `ProductVersion` 是否一致。
- `OfficeAgentSetupCustomActions` 当前属于 ignored 本地目录，版本脚本会在该文件存在时同步/校验，不存在时跳过，避免干净克隆依赖 ignored 文件。
- 已统一以下程序集版本：
  - `AssemblyVersion("2.0.0.0")`
  - `AssemblyFileVersion("2.8.0.0")`
  - `AssemblyInformationalVersion("2.8.0")`
- 已同步 `ExcelAi`、`WordAi`、`PowerPointAi` 的 VSTO `ApplicationVersion` 为 `2.8.0.0`。
- `OfficeAgent.vdproj` 的 `ProductVersion` 保持 `2.8.0`。

验证：
- `powershell -ExecutionPolicy Bypass -File .\build\UpdateVersion.ps1` 可执行。
- `powershell -ExecutionPolicy Bypass -File .\build\AuditVersion.ps1` 通过。

### P0-4 正式代码签名工程入口

- 新增 `build/SignArtifacts.ps1`。
- 支持通过 `OFFICE_AI_SIGN_CERT_THUMBPRINT` 或 `OFFICE_AI_SIGN_PFX` / `OFFICE_AI_SIGN_PFX_PASSWORD` 签名 Release 产物。
- 默认要求待签名产物必须存在，避免 MSI 或 DLL 未生成时误报成功；如确需局部签名，可显式传入 `-AllowMissing`。
- 签名后默认调用 `signtool verify /pa /tw` 验证 Authenticode 签名和时间戳，可用 `-SkipVerify` 跳过。
- 新增 `build/VerifySignatures.ps1`，用于发布前独立验签。

限制：正式证书本身属于外部交付物，当前仓库不能凭空完成证书申请、私钥保管、企业信任链验证。

### 发布前总验收入口

- 新增 `build/RunReleaseChecks.ps1`。
- 默认顺序执行版本一致性审计、安装包 Release 审计、WordAi/ExcelAi/PowerPointAi Release 编译、memory/skills/schema drift smoke、`git diff --check`。
- 支持 `-SkipBuild`、`-SkipSmoke`、`-VerifySignatures`。
- 三端 Release 按顺序构建，避免 SQLite native DLL 复制时互相抢占。

验证：`powershell -ExecutionPolicy Bypass -File .\build\RunReleaseChecks.ps1` 通过。

### P0-1 COM 对象释放基础设施

- 新增 `ShareRibbon/Utils/ComObjectHelper.vb`。
- 已注册到 `ShareRibbon.vbproj`。

状态：基础工具类已落地；本轮已继续覆盖 Word/Excel/PowerPoint 高频 COM 遍历热点。仍建议用真实 Office 长时间会话观察内存和句柄曲线。

### P1-6 WebView2 Environment 缓存

- 新增 `ShareRibbon/Config/WebView2EnvironmentCache.vb`。
- Phase 2 启动阶段增加默认 WebView2 environment 预热。
- 以下共享 WebView2 初始化入口已改为按 `UserDataFolder + AdditionalBrowserArguments` 缓存：
  - `BaseChatControl`
  - `WebViewService`
  - `BaseChat`
  - `BaseDeepseekChat`
  - `BaseDoubaoChat`
  - `BaseDataCapturePane`
  - `ConfigApiForm` skills WebView

验证：WordAi、ExcelAi、PowerPointAi Debug 编译通过。

### P1-7 HttpClient 复用

- 新增 `ShareRibbon/Utils/HttpClientPool.vb`。
- 已迁移主要短生命周期 HTTP 调用点，包括：
  - `HttpStreamService` 主请求、非流式请求、ReAct 续写请求
  - Embedding、意图识别、自动补全
  - 翻译服务
  - 配置页模型列表/API 验证
  - BaseChatControl 非流式内部请求
  - Word 网页图片下载
- 池化后所有 API Key/Auth 均改为请求级 header，避免污染共享 client。

保留项：
- `AiGateway` 和 `OfficeCompletionService` 已经是静态 HttpClient。
- `StreamJsonRpcMCPClient` 属于 MCP client 生命周期，已通过 P1-5 的 `McpConnectionPool` 统一复用。
- `LLMUtil.SendHttpRequest` 带自定义 handler，暂不迁移。

验证：WordAi、ExcelAi、PowerPointAi Debug 编译通过。

### P1-5 MCP 连接池接入

- 新增 `ShareRibbon/Mcp/McpConnectionPool.vb` 和 `ShareRibbon/Mcp/PooledMcpConnection.vb`。
- `HttpStreamService` 的工具归属扫描和实际 `CallToolAsync` 已改为复用池化连接。
- 保留连接初始化、工具列表缓存和单连接串行调用控制，避免每次工具调用都重新创建 client / initialize / list tools。

验证：WordAi、ExcelAi、PowerPointAi Debug 编译通过。

### P1-8 HTTP Streaming 缓冲优化

- `HttpStreamService.FlushBufferAsync` 增加字符阈值和时间片阈值，普通正文不再每个 token 都立即调用 WebView JS。
- 推理内容、状态提示、错误提示和 `[DONE]` 收尾路径仍强制刷新，避免 UI 尾部内容丢失或长时间停留。

验证：WordAi、ExcelAi、PowerPointAi Debug 编译通过。

### P1-9 Streaming 请求取消机制

- `HttpStreamService` 增加 requestUuid 级 `CancellationTokenSource` 注册表。
- 主流式请求、非流式请求和 ReAct 工具结果回注请求均传入 cancellation token。
- 流读取阶段注册 token 回调释放 response stream，避免用户点击取消后仍阻塞在 `ReadLineAsync`。
- 前端停止按钮会携带当前 `requestUuid`，后端 `BaseChatControl.HandleStopMessage` 调用 `HttpStreamSvc.CancelRequest(requestUuid)`。

验证：WordAi、ExcelAi、PowerPointAi Debug 编译通过。

### P0-1 COM 对象释放热点补强

- `ComObjectHelper` 增加强类型泛型重载，便于释放 Word/Excel/PowerPoint 强类型 RCW。
- Excel `Ribbon1` 的选区单元格扫描释放临时 `Range` 和 `Worksheet`。
- Excel `ExecuteCleanData` 释放 `Worksheet`、`Range` 和遍历中的临时 `Range`。
- PowerPoint `Ribbon1` 的幻灯片/形状扫描释放 `Slide`、`Shape` 和临时 `TextRange`。
- PowerPoint `DeepseekControl` 的选中对象和幻灯片分支释放 `Selection`、`Slide`、`Shape` 等临时 COM 对象。
- Word `OpenXmlWordTranslator` 的表格/段落扫描释放 `Table`、`Paragraph`、`Cell`、`Range` 等高频临时 COM 对象。
- Word `WordDocumentTranslateService` 的内嵌图片、公式、表格对象扫描改为索引访问并释放 `InlineShape`、`OMath`、`Table` 及其 `Range`。
- PowerPoint `ChatControl` 的外部 PPT 内容提取路径释放临时 `Slide`、`Shapes`、`Shape`、`Table`、`Cell` 和 `TextRange`。
- PowerPoint `ChatControl.GetSlideTitle/GetSlideContent` 的幻灯片内容解析改为索引访问，并释放 `Shapes`、`Shape`、`TextRange`。
- PowerPoint `ExecuteApplyTransition/ExecuteBeautifySlides` 不再把全量 `Slide` RCW 暂存在 List 中，改为逐张处理并释放；美化字体路径释放 `TextRange`。
- PowerPoint 选中幻灯片摘要复用 `GetSlideTitle/GetSlideContent`，避免重复 `slide.Shapes` 枚举。
- PowerPoint 插入/批量创建幻灯片的标题和正文占位符填充收敛到 `TrySetPlaceholderText`，统一释放 `Shapes`、`Shape`、`TextRange`；新增文本框由 `AddTextBoxToSlide` 释放临时对象。
- PowerPoint 添加动画路径改为索引访问并释放 `TimeLine`、`Sequence`、`Effect`、`Shapes`、`Shape`、`Slide`。
- 当前 `PowerPointAi.ChatControl` 剩余的 `slide.Shapes` 枚举仅在排版模板应用前收集 `_reformatShapes`，这些 `Shape` 会被后续流程持有，不做立即释放。

验证：WordAi、ExcelAi、PowerPointAi Debug 编译通过；追加补强后 WordAi、PowerPointAi Debug/Release 复测通过。
